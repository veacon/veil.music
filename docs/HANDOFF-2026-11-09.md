```bash
  -Dorg.gradle.jvmargs="-Xmx2g -XX:MaxMetaspaceSize=768m -XX:ReservedCodeCacheSize=256m" \
  --console=plain
```

**内存注意事项**：本机曾因多个 Gradle 守护进程堆积 + 测试 JVM 堆落在低 4GB 触发 native OOM（`Unscaled Compressed Oops mode`）。缓解方式：
1. 一律用 `--no-daemon --max-workers=2` 与上面的 `-Xmx2g`；
2. 跑测试前确认没有残留 `java` 进程；
3. 若测试执行器仍 OOM，用临时 init 脚本调测试 JVM 堆基址（**不要写进工程文件**）：

```groovy
// /tmp/verify.init.gradle —— 临时文件，用完删除
allprojects {
    tasks.withType(Test).configureEach {
        maxHeapSize = "768m"
        jvmArgs "-XX:HeapBaseMinAddress=8g", "-XX:MaxMetaspaceSize=256m"
    }
}
# 然后：./gradlew -I /tmp/verify.init.gradle testDebugUnitTest ...
```

## 4. 本轮 4 项需求 · 实现明细

### 4.1 默认设置（用户明确要求）

| 项 | 新默认 | 位置 |
|---|---|---|

### 4.2 web 界面英文完整覆盖

三层机制，全部随语言设置切换：

1. **静态 HTML / JS 文案** → `assets/i18n/phone-en.json`（198 条，长句优先替换）+ `i18n/PhonePage.render()`。
2. **动态提示 / 错误 / 状态**（带变量） → 新增 `i18n/PhoneText.kt`，16 个 key 的中/英模板，用 `String.format`。**注意 Kotlin 字符串里 `%1$s` 必须写成 `%1\$s`**，否则 `$s` 会被当成字符串模板变量（本轮已因此踩过一次编译错误并修复）。
3. **运行时日志行**（`[LX]`、`FETCH`、网络日志、SSE、bugreport） → `PhonePage.localize()`，先按 `LOG_RULES`（30 条整句正则，处理「中文模板 + 动态数字/文件名」）整体转英文，再走字典；避免短词把句子切碎后残留中文碎片。

覆盖点：`InAppWebServer.kt` 的 `html()`、`status()`、`logsJson()`、`netLogsJson()`、`bugReport()`、`:8081` 事件流、SSE 广播、`/lx-import`、`/lx-delete`、`/lx-reload`、`/lx-reset`、`/playlist-import`、`/set-apple-display*`、`bookmark` 指令。
语言协商：`?lang=` > cookie `amtv_lang` > `Accept-Language` > TV 端 `AppLanguage.code`。

**唯一有意保留的中文**：语言切换器里的「中文」（语言名按惯例保留母语写法，与 `English` 对称）。

新增回归测试 `PhoneEnglishCoverageTest`：英文页零中文残留、中文页仍中文、切换即时生效、动态 POST 回复英文、26 条运行时日志样本零中文、16 个动态模板英文变体零中文。

### 4.3 每首歌取链日志

新增 `luoxue/FetchLog.kt`（纯格式化工具，不发请求、不碰缓存、不改解析结果），在 `LxPlayback.doResolveInner()` 命中与未命中两处埋点，输出 `[LX] FETCH {json}`：

| 字段 | 含义 |
|---|---|
| `event` | 固定 `fetch` |
| `ts` | 取链开始时间，UTC ISO-8601 毫秒 |
| `start_ms` | 同一时刻 epoch 毫秒（便于与系统日志对齐） |
| `elapsed_ms` | 从开始到出结果的总耗时（成功/未命中/异常都记） |
| `song_id` / `title` / `artist` / `album` | 可唯一定位歌曲的标识 |
| `result` | `ok` / `miss` / `cache` / `error` |
| `source` / `quality` / `kbps` / `script` / `attempts` / `reason` | 诊断字段 |

一行一个 JSON，便于 grep / 导入表格统计。新增 `FetchLogTest`。

### 4.4 Apple Music 展示登录 + 开关（硬约束：仅展示，播放不回流）

新增 `data/AppleDisplayAuth.kt`：

- **独立存储** `apple_display_prefs`，与既有 `MutPreferences` / 播放 token 完全隔离；
- **默认关闭**。关闭时 `refresh()` 是纯 no-op，不发一个字节网络请求、不暴露账号状态；开启才抓取 Bearer 并校验 MUT；
- **URL 白名单** `isDisplayOnlyUrl()`：只放行 `https://music.apple.com/`（抓 Bearer）、`/v1/me/storefront`、`/v1/me/account`、`/v1/me/social/profile`、`/v1/me/library/playlists`、`/v1/me/library/recently-added`、`/v1/me/recommendations`；任何含 `webplayback` / `mzplay` / `playbackinfo` / `hls` / `stream` / `drm` / `license` / `widevine` 的 URL 一律拒绝；
- 数据只进 `StateFlow<State>`（`storefront` / `accountName` / `displayItems` 纯文本歌单名），**绝不含播放地址**；
- 不复用播放用的 OkHttp 客户端，不改动 `luoxue/` 播放取链逻辑与 `PlayerViewModel` 播放分支；**播放直链始终由落雪音源解析**。

接入点：
- web 配置页：`InAppWebServer.kt` 的 `/set-apple-display`（开关）、`/set-apple-display-token`（登录）、`/set-apple-display-signout`，以及开关开启时显示的展示卡片；
- TV 设置页：`ui/screens/DevMenuScreen.kt` 新增「Apple Music 展示」区块的 `Toggle`，与 web 端共用同一单例 StateFlow；
- 新增 `AppleDisplayAuthTest`（默认关闭、关闭时零请求、独立存储、播放端点硬隔离）。
