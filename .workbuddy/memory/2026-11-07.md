## 歌词字体加载 0% 修复
- 根因：上轮把 `AppFonts.get(this).start(appScope)` 删了（改成苹方内置），但 `ProvideTvFontWeights` 仍 `fonts.state.collectAsState()` 读下载状态，`FontDownloadState` 默认 phase=Loading，`FontGatedLyrics` 按 `state.ready` gate，永远卡「歌词字体加载中 0%」。
- 修复：`ProvideTvFontWeights` 直接提供恒 Ready 的 `FontDownloadState(phase=Ready)`，不再读 AppFonts；歌词 gate 放行。苹方 `PingFangFamily` 作为唯一 family。
- 模拟器验证：播放「我对缘分小心翼翼」flac 1714kbps + 网易云歌词 53 行，歌词区正常显示（含 COMPOSER/LYRICS 行）。

## 音源优中选 10（lx-hunter）
- 需求：参考 https://github.com/zlyon/lx-hunter 提取脚本，优中选 10。
- lx-hunter 是 Songloft 插件，内置 30 个 GitHub 音源仓库（`main.js` 的 `DEFAULT_REPOS`），本身不存 .js，靠爬仓库文件树提取。
- 关键仓库：`guoyue2010/lxmusic-`（按音质分级：优质-四平台FLAC/良好-两平台FLAC/一般/较差）、`javon4016/xgzy-mysources`、`fengyvle/yyt-music-sources`、`pronii/lx-music-qdy-mini` 等。
- 拉取 15 个新脚本到 `lx_candidates/`，构造 bench_run（22 脚本 = Top8 复测 + 14 新候选），push 模拟器跑 LxBench（3 曲）。
- **坑**：①中文文件名 adb push 会被截断/乱码，必须转 ASCII（c01~c13）；②新脚本里 c03(KE-DES)、c07(sixyin-music-v107 1.4MB) 触发 QuickJS 栈溢出崩溃（SIGSEGV stack overflow），须移出；③bench 模式读内部 `files/bench`（run-as cp 进去），外部 getExternalFilesDir 路径 scoped storage 下 adb push 不被 listFiles 识别。
- **实测结果（19 脚本/146 次/46 成功）**：kulao 8/9、hyw 7/9、fish 5/9、**Ciallo～ 3/3 wy 320k（新增）**、**qdy-mini 3/9 wy 320k（新增）**、xinghai 3/9、quandou 3/9、molan 3/9、**回避聚合 2/9 kg 320k（新增）**、jiexiang 3/9。
- **最终 10 个内置音源**（assets/luoxue）：lx-01-kulao、lx-02-hyw、lx-03-fish、lx-04-xinghai、lx-05-quandou、lx-06-molan、lx-07-hubhui(回避聚合，替换 xinglan)、lx-08-jiexiang、lx-09-ciallo、lx-10-qdy。
- `AudioResolver.PREF` 更新：wy 加 lx-09-ciallo/lx-10-qdy（320k 优质），kg 的 xinglan 换成 hubhui。
- `LxScriptStore.syncFromAssets()` 自动处理新增/淘汰脚本（manifest hash 对比），无需硬编码清单。

## 2.0 Veil Music 重构（品牌 / 布局 / 持久化）
- 包名整体迁移：`com.applemusic.lavande` + `com.applemusicktv` → **`com.veacon.veilmusic`**（namespace 与 applicationId 都换）。
  源码目录 `com/applemusicktv` → `com/veacon/veilmusic`（main/test/androidTest 三处），322 个文件的 package/import/manifest/proguard 用 Python 二进制替换（注意先替换更长的旧 applicationId）。
  应用名 `Apple Music TV` → `Veil Music`；versionName 2.0 / versionCode 200（`app/release-version.properties`）。
  `LxPocActivity` 摘掉 MAIN/LAUNCHER，桌面只留一个图标，诊断页改用 `am start -n com.veacon.veilmusic/com.veacon.veilmusic.luoxue.LxPocActivity`。
- **踩坑**：改 namespace 后 Hilt 生成物残留旧包，`hiltJavaCompileDebug` 报 `找不到 com.applemusicktv.AppleMusicApp`；
  删 `app/build` 不够，KSP/Hilt 增量缓存会还原旧输出 —— 必须 `./gradlew clean --no-build-cache`。
- 「左侧/下侧遮挡、无法全屏」根因：`BottomNavInset = 102.dp` 是给一条**早已没人调用的** `NowPlayingBar` 预留的视口内缩，
  每页底部白丢 102dp，最后一行永远被切在屏幕下沿。改 32dp；`TopNavInset` 100→96dp；Genre/Search 底距统一引用常量。
- 「配置音源」弹窗：`fillMaxWidth(0.8f) × fillMaxHeight(0.8f)` + 列表 weight(1f)；每行左列名称/状态/源平台、右侧 92×38dp 按钮同行右对齐、文字居中；删掉无行为的「检测」按钮；入口副标题同步去掉"连通性检测"。
- 资料库侧边栏顺序改为 歌曲 / 歌单 / **最近播放** / 专辑 / 艺人（`LibrarySection` 声明顺序即 UI 顺序）。
- 持久化加固：`LocalLibraryStore` 写入改 `FileOutputStream + fd.sync()` + rename；解析失败把坏文件另存 `local_library.corrupt.json`（否则下次 persist 会用空数据覆盖用户歌单）。
  `DiskBudgetStore.file()` 显式拒绝前导 `/`（Windows 上 `File("/tmp/x").isAbsolute == false`，单靠 isAbsolute 挡不住）；写入改 `Files.move(REPLACE_EXISTING, ATOMIC_MOVE)`。
- 升级链路改 GitHub Releases：清单 `<repo>/releases/latest/download/update.json`，APK 必须落在同仓库 `releases/download/` 且 `.apk` 结尾；
  `updateHttpClient` 加白名单跳转跟随（github.com / objects.githubusercontent.com / release-assets.githubusercontent.com），原来 `followRedirects=false` 会让 GitHub 302 直接失败。
- 测试：`gradlew testDebugUnitTest` 从 26 红降到 0 红。主要是历史文案/域名期望过期（`跳过，仅试听`→`不登录，直接使用`、`api.music`→`amp-api.music`、`pages.dev`→github Releases），
  以及手机配置页不再有令牌表单（`PhoneLoginTest` / `V29PhoneLocalizationTest` 的登录区块用例已随功能下线）。
- 模拟器验证：1080p 下 `pageHorizontalInset` 命中 120dp 上限、内容 1920-2*210；首页第二行卡片不再被底部切断；弹窗实测 79.6% × 80.3%。
- **推送受阻**：`HTTPS_PROXY=http://127.0.0.1:51829` 返回 `CONNECT tunnel failed, 502`，清空代理后直连 github 也超时 —— 提交已在本地，需可用的网络/代理再 push。

## 仓库合并到 veil.music + 2.0 发布
- 决策：只留一条线。`veacon/veil.music` 为唯一发布线，旧的 `com.veil.music`（v1.1.2 / minSdk 26 / arm64）归档在
  同仓库 `legacy-1.1.2` 分支与同名 tag（API 直接建 ref，旧 main sha 352be93）。
- `UPDATE_BASE_URL` → `https://github.com/veacon/veil.music`；清单 `releases/latest/download/update.json`，APK `releases/download/v2.0/Veil-Music-2.0.apk`。
- **网络坑**：这台机器 git 走 `HTTPS_PROXY=127.0.0.1:51829`，`github.com:443` 的 CONNECT 反复 502 / schannel 断连，
  但 `api.github.com` 与 `uploads.github.com` 通。于是写了 `tools/gh_push_tree.py`：
  用 Git Data API（blobs → tree → commit → PATCH ref）把整棵树推上去，489 文件/6 线程约 2 分钟。
  本地 commit 与远端 API 生成的 commit sha 不同（parent 不同），内容一致；两边靠 remote 区分（origin=AMusic-ATV，veil=veil.music）。
- Release v2.0 已发（id 437347334），asset：`update.json`(478) + `Veil-Music-2.0.apk`(19648655, sha256 829ec135…)；tag 已对齐最终 commit 40f7dce。
- **在线升级实测失败**：模拟器点「检查更新」报错，日志 `check failed: IOException: Required SETTINGS preface not received`，
  改成 HTTP/1.1 后变成 `SocketTimeoutException ... github.com/20.205.243.166:443 after 20000ms` —— 模拟器所在网络到 github.com:443 的 TCP 直接被阻断
  （ICMP 能 ping 通，属典型干扰）。代码侧已做的：HTTP/1.1、20s/30s 超时、CDN 重定向白名单、清单与 APK 同仓库同路径校验。
  真机若也访问不了 GitHub，需要给更新清单加一个国内可达的镜像地址。
