用户决策：纯自用 / 无 PC / 直接用社区脚本 / 保留 Apple 品牌 / 5% 失败自动换源 / 要高音质+MP3 兜底 / 不保留个人库（抓 Apple 未登录通用数据）/ 先做 P0。

- 核心结论：
  - 裸测（只给歌名+歌手）：15 个脚本仅 1 个可用（K×H），且**只出 128k MP3**，请求 master 也静默降级。
  - 带平台 ID：7 个脚本出真 FLAC，最高 3534 kbps（wy master）。
  - 全链路 20 首：**19/20 命中（95%）、18/20 真 FLAC（90%）、中位 4567 kbps**；解析 p50 239ms / p90 3.3s / 最坏 40s。

  - 直链 TTL 实测 ≈21 分钟（163 URL 内嵌时间戳）；FLAC 的 Content-Type 谎报 audio/mpeg，必须按扩展名/魔数设 mimeType。
- 架构定稿：端内 QuickJS 跑脚本 + Kotlin 自建搜索层 + 脚本级联 + 直链校验，无服务端。

### 踩的坑（重要）
1. **Kotlin 块注释可嵌套**：KDoc 里写 `` `/v1/me/library/*` `` 的 `/*` 会开新注释 → 报 "Unclosed comment"，且 KSP 会连带报一堆 "LocalLibraryStore could not be resolved"。
2. **ViewModel 属性顺序**：`_state = MutableStateFlow(LibraryState(sort = loadSavedSort()))` 里用到 `cachePrefs`，
   而 cachePrefs 声明在后面 → 启动 NPE（`SharedPreferences.getInt on null`）。初始化顺序必须 cachePrefs 先。
3. **TV 截图不可靠**：exec-out screencap 会拿到旧帧（多次 md5 相同）。改 `screencap -p /sdcard/x.png` + pull，
   真正判断界面状态用 `uiautomator dump` 读 text/bounds（1920x1080 设备坐标）。
4. **adb forward 会被 adb connect 清掉**：每条命令前重建 `forward tcp:18080 tcp:8080`，否则 curl 得到空响应。
5. 本机 curl 走系统代理会报 `upstream connect failed (10061)`，访问 127.0.0.1 要加 `--noproxy '*'`。
6. 播放页 / 详情页 Back 不回退时，直接 `am force-stop` + 重开最省事（数据已持久化）。

### 顺带修的真 bug
`AudioResolver` 原来只认 `kind==flac || kbps>=200`，但脚本多数不返 bitrate、文本导入也没时长 → kbps=0，
5MB 的正常 mp3 被 0kbps 门槛误杀（"全部源失败"）。改为：kbps 未知时 `bytes >= 1.8MB` 也算完整曲目。
修复后 Yesterday 从 26s 全失败 → 5.2s 命中 wy。
